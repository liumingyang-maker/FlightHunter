# 执行节奏建议（保留 MiMo 工程独立性）

以下仅为对项目现行 `AGENTS.md` 中“每次小改动都生成 GPT 审核包”工作流的**本批任务临时覆盖建议**。安全与合规条款不可覆盖，代码实现由 MiMo 自主选择。

> **本次用户授权：集中完成三大核心目标后提交统一审核包。**
>
> - 开发期间继续使用 `develop` 分支、正常 Git 提交、CI、单测、集成测试和 Windows 实机调试；保留关键日志。
> - 不需要每修一个函数、跑绿一个测试就打包让用户找 GPT。仅在最终业务闭环完成时输出一次综合审查包。
> - 发生真实安全风险、数据破坏、需要授权的外部动作等阻断时先停用该危险路径，继续不依赖的其他功能；只有非用户无法决定的问题才一次性集中询问。
> - 不能用 Mock/Fixture/成功 HTTP 状态替代真实报名、真实领券或真实可购买价格；不会做的写 blocked/partial，不能写 done。
> - 我的审核意见是建议，不是必须遵照的逐条修复指令。MiMo 根据实际工程做选择，并在最终报告解释重要差异。
> - 不自动合并 main，不 force push，不自动付款、不自动真实外站提交、不绕过 CAPTCHA/2FA/平台禁止自动化的要求。

## 怎么提速才靠谱

**节约的是人工审核往返，不是测试。** 推荐先锁定领域接口和数据库迁移，再根据风险将来源发现、三大引擎、浏览器、提醒、UI 分模块推进，随每次提交持续测试。只有最后进行总集成检查和一次独立 GPT 审核。

先行使用现有代码、保留迁移和业务历史，不为“想写得漂亮”重建现有系统。在每一个实用用户旅程中同步完成后端/API/页面/通知，而不是先写一堆彼此孤立的 service。

MiMo 交付时只发送一条**简明最终汇报 + 一个可审阅的真实 ZIP**；不需要在不同 AI 之间来回复制中间修复清单。
