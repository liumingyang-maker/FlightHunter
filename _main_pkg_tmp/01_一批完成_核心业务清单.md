# 核心业务实施清单｜一批完成三大目标

## A. 总目标、进度口径

本次是 FlightHunter 完整 V1.0 的一次集中交付，不拆 MVP、不拆四个版本、不以测试数量代替真实可用度。**保留并复用现有代码**；先确认功能现状，再只补缺口。完成状态定义：

- `done`：具备真实可调用执行路径、有测试、有相应运行证据，能符合产品预期；外部需要专属授权的操作按下面的可用性分级。
- `partial`：代码模块存在，但未贯通数据库/UI/通知或缺少关键实机证据。
- `blocked`：第三方接口授权、地区/网站规则、用户凭据、网络访问等客观障碍；须写明阻碍与不越界的替代方案。
- `not_implemented`：无有效实现；绝不能用 demo、mock、接口类、TODO 冒充 done。

验收分级必须明确：**本地模拟 E2E 通过** ≠ **公开网页只读采集通过** ≠ **真实商家领券成功** ≠ **真实航班两人可订价已验证**。项目各页面和汇报中统一使用这些区分。

## B. 目标一：无人值守监控与可靠通知（优先级高）

**已有基础：** `app/scheduler/jobs.py`、worker/`scan-due`、`scripts/install_worker_task.ps1`、`app/services/notify/`、通知 UI/API 等。不得另造平行调度系统。

- [ ] **MON-01 启动与重启**：Windows 开机/登录后能按用户同意的方式拉起后台扫描；PowerShell 安装、停止、卸载、查看任务状态均可操作。没有用户授权不得擅自改系统设置。
- [ ] **MON-02 连续工作**：后台扫描在网络中断/重启后能够恢复；追踪上次成功/失败及下次计划时间，禁止仅打印 `completed` 就算真实抓取成功。
- [ ] **MON-03 执行安全**：扫描任务有租约、原子幂等、到期任务按到期时间筛选再分页，适用并发限制/域名限流；`dry-run` 绝不占用真实执行额度或更新时间。
- [ ] **MON-04 来源复用**：重复行程/相同来源可复用抓取缓存与结果，避免同一网页短时间内被多任务重复请求；来源标签和国家/城市匹配不能凭空编造。
- [ ] **MON-05 全链路通知**：发现有效机会后能实际写入通知；本地弹窗/手机通道需显示尝试、成功送达、失败/待补发的真实状态。仅 stdout 不得当作送达。临近截止做去重和离线恢复提醒。
- [ ] **MON-06 可观察性**：控制台显示服务健康、上次抓取时间、成功来源数、候选数、已核实数、失败原因、费用预算和实际下次运行时间。用户可禁用/调整频率/查看日志。
- [ ] **MON-07 安全门槛**：真实联网采集前保证 SSRF / DNS 重绑定 / 逐跳重定向 / 私网地址防护、外部 HTML 为不可信指令、robots 与站点规则、超时限流。未达到门槛则继续在隔离适配器或只读/手动来源运行。

**验收关键：** Windows 真实调度至少成功触发多轮扫描，包括一次失败/恢复；数据库、UI 与外送通知状态相符，禁止把离线 Mock 统计成在线扫描。

## C. 目标二：真实来源与三大引擎业务闭环（产品价值核心）

### C1 共享来源引擎

- [ ] **SRC-01 来源目录**：建立/核实航空公司、各国旅游局、当地商家、交通景点、中文机票信息社区的可合法获取来源；按来源国家/语言/类型/更新时间/可否自动访问维护健康表。无公开合法接口的渠道保留人工粘贴 URL/文字/截图导入。
- [ ] **SRC-02 真正抓取/解析**：RSS/Atom、公开 HTML、sitemap、官方活动页/条款页适配器可运行，保留来源 URL、最终落地 URL、提取时间、内容哈希、活动期和字段级原文证据；区分只看到标题和拿到完整官方条款。
- [ ] **SRC-03 多语言与去重**：支持设计中的 14 类语言检索词；同源跨语言、转载/正文、重复轮次识别；规则变更触发重新评估，过期/撤销自动降级。
- [ ] **SRC-04 AI 降本和安全**：DOM/规则抽取优先，复杂页面可使用用户配置的兼容 API；结果必须校验并关联公开证据；模型输出不能自授报名、券领取、网络或文件权限。缓存稳定页面，限制 Token/抓取预算。
- [ ] **SRC-05 质量演示**：至少对多个来自不同类型的**真实公开可访问来源**给出只读抓取日志和结果；未抓到或被禁止抓取的站点用 `blocked/manual_only` 标记，绝不编造实际活动或公开来源覆盖率。

### C2 全球抽奖猎手（Giveaway）

- [ ] **GIV-01 发现与验证**：公开活动线索 → 主办方/托管官网关联 → 官方规则证据 → 活动期/资格三态 → 可参与推荐；不能凭“Official Rules”或关键词将证据不足活动升格为 verified。
- [ ] **GIV-02 资格与奖品实际价值**：按档案分别判断国籍、合法居住地、年龄、每人/每户限额、免费报名方式、同行人数、起飞机场、可用时间和额外费用；未知不可判可参加。
- [ ] **GIV-03 合规报名**：Playwright 模板缓存、预填/人工审查/回执识别，状态与数据库同步。真实外站提交默认关闭；只有规则明确允许且用户对对应活动授权才可单次提交，验证码/证件/支付/社交分享强制人工处理。
- [ ] **GIV-04 Windows 实机模拟**：本地安全模拟站由真实 Chromium 操作，`prepare → awaiting_review → submit → receipt → DB → UI → notification`；模拟回执不得写到真实活动；提交后无确认必须 `unknown` 并禁止重复重提。
- [ ] **GIV-05 异常恢复**：断网/浏览器意外退出/用户中断/连续两次演示等情况不能造成半提交、双提交、错误成功；reconcile 只能处理真正超时且没有执行租约的任务，不得误关活动中的报名。

### C3 行程福利猎手（Trip Benefits）

- [ ] **TRP-01 行程输入**：用户首次添加日期/国家/城市分段，后续自动持续发现并随行程变化重匹配；例如 2027-05-10～05-30 日本是**演示数据，不是用户已确定的真实行程**。
- [ ] **TRP-02 多类真实福利**：官方券、商家/支付卡优惠、交通住宿景点门票、地方活动、免费体验及预约。区别可领取、可预约、实际可用、活动举行日期，未公布的下一年活动只能历史参考。
- [ ] **TRP-03 资格与节省**：核验具体地区、日期、身份、发卡国家/支付方式、最低消费、能否叠加，按**真正计划消费**计算可节省金额；没有官方依据不冒充可用。
- [ ] **TRP-04 合规领券/卡包**：免费且明确允许自动领券时由用户授权的站点适配器执行；无权限则提供官方领取入口和中文操作说明。`saved / claimed / used / unknown` 严格区分，动态 App 券不保存过期截图，私有码加密保存并可删除。
- [ ] **TRP-05 中文使用说明与提醒**：每条权益说明领取方法、开放/预约/可用日期、城市门店、最低消费/付款、核销步骤、排除项与官方依据；领券开始、预约、到期、旅途中使用提醒，撤销规则立即提示。
- [ ] **TRP-06 完整演示**：已知官网/模拟来源 → 结构化条款 → 行程匹配 → 公开券 `saved` / 授权模拟领券 `claimed` → 钱包查看 → 中文指南 → 提醒 → 行程修改重新评估；不要把模拟券码冒充真实资产。

### C4 全球低价机票捡漏雷达（Fare）

- [ ] **FAR-01 全球信号**：抓取/导入中文社区及官方促销线索，识别 BUG/错价/漏油/甩尾/临期/候补/放票等，关联航段、币种、适用日期、人数及原帖、发帖时间；无证据只显示情报。
- [ ] **FAR-02 真实报价接口**：优先合法授权的航司/OTA/公开 API；用户没有 Key 或平台条款不允许时，提供官网查价快捷入口和清晰的“未核实报价”状态，**不允许伪造实时可购性或绕过反机器人保护**。
- [ ] **FAR-03 双人成本和有效性**：核实两人（可配置）可用库存、出发机场、往返日期、含税、行李、定位、转机/联程、汇率和取数时间；未知费用不报精确总价；爆料与实测报价分层，过期立即降级。
- [ ] **FAR-04 价格历史与通知**：同航线/日期条件可比才建历史基准，样本少不吹“历史最低”；真正有可信查询源才可 `urgent_verified`，其余作为未核实爆料。风险票隔离展示，不自动订票/付款。
- [ ] **FAR-05 完整演示**：一个真实公开爆料或合法公开促销 → 提取 → 去重 → 匹配用户 CKG/TFU 等愿望单与预算 → 显示原始信息/风险/报价状态 → 合理的提醒；如真实报价不可得，只演示 `unverified` 的诚实降级。

## D. 目标三：把浏览器、卡包、邮件、通知与 UI 接成用户流程

- [ ] **INT-01 浏览器执行器**：复用 `app/services/browser/playwright_exec.py`，支持 Windows `file:///C:/...`、空格、路径 Unicode 处理；预填绝不自动提交，模拟提交需要明确本地测试授权。真实外部默认只读/人工预填，并严格区分 `confirmed/unknown/failed`。
- [ ] **INT-02 领奖邮件**：IMAP 只读候选（用户授权后）或本地 `.eml` 模拟信箱，核验发送者/官方域名/活动关联，钓鱼邮件不得自动判中奖；不自动回复、不访问危险附件。真正读取外部邮箱时须有可回溯证据（脱敏）。
- [ ] **INT-03 加密钱包**：Windows DPAPI 或安全的加密后备方案，读写密钥/券码/凭据全闭环；泄露测试、重启恢复、删除与撤销、仅局部脱敏显示。不能只凭 `encrypt=true` 配置即宣称完成。
- [ ] **INT-04 用户页面**：首页 → 找机会/机票雷达/行程 → 详情与原文证据 → 报名中心/钱包/通知 → 设置，用户可实际操作；手机宽度能看、登录鉴权保持生效，不因新增 API 暴露隐私。
- [ ] **INT-05 通知落地**：站内 + 用户开启的本机 Toast/手机渠道；明确 `stored / attempted / delivered / failed`，不把“写数据库成功”当作推送成功；通知点开能回到对应的活动、机票或优惠详情。
- [ ] **INT-06 Windows 实机环境**：uv、Python、Chromium、依赖、数据库迁移、后台任务及健康检查形成一套可执行安装与操作说明；从干净数据目录启动，重启后还能恢复。

## E. 收尾集成与上线安全门槛

- [ ] **FIN-01 全部 114项需求 / 104项验收对照**：使用仓库当前追踪文件和原始设计需求，逐项记录 `done/partial/blocked/not_implemented`；每个 done 有测试/功能/日志链接。不要把单元测试数量当作验收数量。
- [ ] **FIN-02 本地模拟和真实只读验证分层**：Windows Playwright 实机模拟、真实网站只读抓取、IMAP/通知实际送达分级记录；当账号/服务不可用，真实运行项一律说明受限。
- [ ] **FIN-03 安全与隐私**：不绕验证码/2FA/支付，不违规自动提交；URL/私网/DNS 重绑定防护，敏感凭据加密，导出脱敏，个人资料不进云端/仓库/日志。
- [ ] **FIN-04 自动化质量**：pytest、ruff、必要类型检查、数据库迁移、任务多次运行和系统重启的回归；测试失败不能伪造或隐藏。
- [ ] **FIN-05 文档与交付**：更新 README、Windows 安装与用户操作手册、接口说明、来源规则、用户授权说明、软件截图/日志索引；只在最后生成一份汇总报告和一次完整 GPT 审核包。

## F. 何时算“开发完成”？

**三个业务目标的可合法实现部分**都必须有真实可调用路径及对应证据；用户的无账号/无 Key 情况可采用真实的“受限/待授权”运行状态，保留手动操作路径，不得 Mock 代替。若存在 BLOCKER 未通过或待用户授权的不可替代外部动作，最终报告必须显著列明，**不得写“全部完成 / 100% 完成”**。

任务优先顺序可自行优化；与其一天只修一个正则，不如把来源抓取 → 可信判断 → 数据库 → UI → 通知打通做成横向业务闭环。每个模块持续自测，所有跨模块集成在本批任务内完成。
