# FlightHunter V1.0（R3）：需求实施追踪表

**用途：** 交给 Codex 每次提交代码后更新状态；全部属于完整 V1.0 的验收范围，不代表分版本开发。

状态允许值：`not_started / in_progress / done / partial / blocked`；`done` 必须附相关代码、自动测试及证据链接。下列初始状态全部为 `not_started`，因为本设计包**尚未开发软件**。

## 使用规则

1. Codex 修改状态时，应同时提供对应文件名/测试用例/验证截图/运行日志。
2. `blocked` 必须描述外部限制（站点禁止、需要本人授权、缺少公开规则）和合法的替代方案。
3. `partial` 不能冒充 `done`；真实外部网页 dry-run 未完成应如实注明。
5. 每次 CI 报告同步本表，最后根据阻断用例决定是否达到 V1.0 的交付标准。
6. R2行程福利 `TRIP-01～24` 和 `T48～72` 也是 V1.0 必做，无论旧61项是否已完成。
