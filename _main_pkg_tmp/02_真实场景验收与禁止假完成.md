# FlightHunter V1.0｜统一验收协议（防 Mock 冒充 Done）

## 一、证据分层与等级

| 层级 | 说明 | 可以证明 | 不能证明 |
|---|---|---|---|
| L0 静态实现 | 有代码/接口/数据表 | 模块存在 | 可以运行、已验收 |
| L1 离线自动测试 | 真实执行 pytest、模拟 HTTP/数据 | 约束/逻辑在测试范围有效 | 真实网站可抓/库存可查 |
| L2 本机实机集成 | Windows + 真实 Chromium/DB/任务/通知 | 本地端到端执行与持久化 | 真实外站一定兼容 |
| L3 公开来源只读 | 有合法访问且保留 URL/时间/实际响应 | 某具体来源确实能获取/解析 | 真实报名、领取、库存或可买报价 |
| L4 外部获授权操作 | 经用户授权和站点规则允许，凭据可验证 | 对应一次真实领取/报名/送达 | 推广到所有网站均可用 |

`done` 只能对应**自身实际业务范围**和相应证据层级；例：`真实 RSS 抓取` 至少 L3，`本地模拟浏览器报名 E2E` 至少 L2，`真实两人可买报价` 应有可信的授权来源、时间、人数与库存证据，不能用 L1 冒充。

## 二、16 个端到端验收场景（全部纳入最终报告）

| ID | 要求 | 通过证据 | 阻断性质 |
|---|---|---|---|
| E2E-01 | 在 Windows 干净环境安装、迁移数据库、健康检查并打开 Web | CLI/启动日志，迁移版本，截图脱敏 | BLOCKER |
| E2E-02 | Windows 任务计划/后台 worker 真实唤醒至少两轮，模拟一次离线/恢复 | 时间戳、TaskRun、任务日志 | BLOCKER |
| E2E-03 | 两个以上不同合法公开来源通过真正 RSS/HTML 解析并保存证据 | 公开原始 URL、响应快照哈希、入库 ID | MUST |
| E2E-04 | 真实抽奖来源 → 官网规则 → 三态资格 → UI；证据缺失不得 verified | 真实公开页只读记录+不同资格夹具 | MUST |
| E2E-05 | 本地 HTML 抽奖站由真实 Chromium 完成预填、人工确认、模拟提交、回执、DB 和 UI、通知 | Windows Playwright 运行日志、DB 脱敏记录、UI 截图 | BLOCKER |
| E2E-06 | 上述演示第二次运行不重复报名；超时/点击后异常归 unknown，禁止盲重试 | DB 事务记录及负向测试 | BLOCKER |
| E2E-07 | 模拟数据与真实活动隔离，已确认模拟回执不能污染真实活动 | 负向测试和 DB 关联查询 | BLOCKER |
| E2E-08 | 输入 2027 年 5 月 10–30 日**模拟**日本行程，无城市可见全国优惠，地方未确认 | 行程匹配及 UI、数据状态 | MUST |
| E2E-09 | 城市分段、领取日期/预约日期/使用日期冲突时绝不错误判定 usable；活动未公布需降级 | 至少覆盖“3月领5月用”“5月领6月用”夹具 | BLOCKER |
| E2E-10 | 公开券只保存、模拟领券须真实回执，钱包/加密/中文指南/提醒/撤销链路贯通 | DB、加密后原文不可见、重启恢复、UI | MUST |
| E2E-11 | 导入真实公开国际机票促销/社区爆料 → 提取/去重/分类/愿望单匹配 → 展示可信度/风险/提醒 | 真实公开 URL 与 DB 截图、提醒日志 | MUST |
| E2E-12 | 没有可用授权报价 API 时，`quote_status=unknown/not_queried`，绝不写“已确认可购/两人有票” | 负向测试与 UI 截图；有合法 API 时追加实测结果 | BLOCKER |
| E2E-13 | 本地 `.eml` 真假中奖通知过滤，用户授权 IMAP 后可只读且撤权有效 | 邮件测试夹具/可选真实账户脱敏日志 | MUST（真实 IMAP 需授权） |
| E2E-14 | 通知“记录成功 ≠ 外送成功”，弹窗失败/断网后续有实际状态及补发规则 | 投递日志、通知 UI、真实系统弹窗或明确不可用 | MUST |
| E2E-15 | 外站 URL 私网、DNS 重绑定、重定向等不安全地址，不应到达请求阶段；公共源 obey 条款 | 本地隔离 HTTP/DNS 测试，无内部服务访问证据 | BLOCKER（联网前） |
| E2E-16 | 真实用户从 Web 操作三大引擎：新建行程、设机票监控、看抽奖证据、打开报名中心/钱包/通知；手机适配、鉴权成立 | 录屏/截图（无私人数据）、API 日志、可复现操作 | MUST |

对于必须联网才能验收的 E2E-03、04、11，如环境网络被阻断或来源网站禁止抓取，记录尝试的具体时间、目标域名、异常和被授权的替代渠道，**不得宣称通过**。测试可以给出明确 `blocked` 和正常降级功能，但不能用模拟结果顶替 L3。

## 三、其他规定：114/104追踪与“未完成”的定义

- 以 `reference/R3_原始需求追踪_114项.md` 和 `reference/R3_原始验收_104项.md` 为历史基线，结合仓库最新设计及实际源码形成**当前**追踪表；历史原文 `not_started` 不是当前进度。
- 保留 I1–I12 不变量；其中身份/资格三态、重复报名和重复领券、模拟隔离、社区爆料/报价分离、未知费用、日期证据、禁止未经授权的提交、隐私泄露是不可妥协的底线。
- 使用夹具或 Mock 验证单元逻辑没有问题，但必须在最终报告中标注 L1；不许将 `mock` `fixture` `demo_only` `dry_run` 的结果呈现为真实用户领券/报销/出票/中奖。
- 所有状态和时间需要一致：采集成功、解析成功、资格核实、可领取、已领取、使用完成、真实送达，各自独立。数据库成功 commit 不等于用户已经收到通知。
- 涉及证件、支付、购买、发帖、回复邮件、验证码和真实网站提交，遵守平台条款并要求用户授权；不可因“自动化程度”牺牲安全。
- 真实外站自动提交**不是**这次完整 V1.0 的强制验收；在无法取得许可时应以合规的预填+人工确认作为可用降级，不强行执行。

## 四、工程验收（程序持续自动执行，最后统一汇总）

1. 每个主要模块合并前：对应单元/集成测试全绿，ruff 全绿；测试退出码真实保存。
2. 全部功能集成后：`uv sync --extra dev --python 3.12`、`uv run ruff check .`、`uv run pytest -q`、数据库 migration 升级/恢复检查；新增 tests 必须覆盖功能边界。
3. Windows 主机：安装 Playwright Chromium，跑 `demo-browser-e2e --submit`，并检查 SQLite/回执/网页/通知一致性；测试过程禁止接入真正活动账户。
4. 后台扫描：真实可访问来源的只读网络 smoke test + 断网/重启/重复任务测试；所有网络日志保存脱敏。
5. 安全：访问控制/密钥管理/内部地址绕过/重定向防护/日志敏感数据/动态优惠码/重复提交均有负面测试；失败不准伪造全绿。
6. 最终：提供可独立重跑的结果索引和 `review_exports/FlightHunter-review-<HEAD>.zip`，只做一次最终用户交接。

建议再加 1 次 Windows 真实场景的连续多轮运行观察，模拟时钟调度不能单独证明系统重启恢复有效。如果无法完成长时间观察，直接说明验证窗口，别用“稳定运行24小时”描述未发生过的事。
