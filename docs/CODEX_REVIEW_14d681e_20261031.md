## 问题与建议

### C14-01 · P1 · 浏览器网络拦截不满足连接期安全目标

- 位置：`app/core/browser_safety.py:35-59`；调用位置 `app/services/browser/playwright_exec.py:176-182`。
- 证据：同源请求在第 49 行直接放行，没有调用 DNS 安全检查。模拟中把解析检查设置为抛异常，同源请求仍执行 continue，检查调用次数为零。其他通过公网 DNS 检查的跨源请求也被允许，与注释中的“仅允许同源”不一致。浏览器自身网络连接也没有由此代码绑定到已检查 IP。
- 风险：目标主机解析变化时存在 DNS 重绑定风险；已知逻辑缺口不等于本轮已实地证明完整攻击链。当前不应把浏览器网络边界标为 done。
- 建议：先明确允许的浏览器访问能力和威胁模型；对所有导航、重定向、子资源、弹窗及相关协议制定默认拒绝策略；采用能保证连接时目的地址经过约束的方案，不能仅依赖请求前 DNS 检查。若短期不能保证，禁用或隔离真实外站浏览器自动化，并在 UI 和报告中明确 blocked/partial。
- 验收：新增针对同源 DNS 变化、跨域、公网到私网重定向、子资源和弹窗的测试；优先在隔离环境做真实浏览器集成测试。不得访问真实内部服务作为测试目标。

### C14-02 · P1 · doctor 修改旧数据库表结构

- 位置：`app/cli.py:49-84`，其中第 79 行直接执行 `init_db(engine)`。
- 证据：使用隔离的内存 SQLite，初始只有 `legacy_only` 一张表；调用 doctor 后表数为 35。该过程未接触正式数据库。
- 影响：体检命令可静默创建缺失表，违反旧库不静默改表的目标。create_all 也不能替代数据库迁移。
- 建议：doctor 做只读连接及版本检查，清晰显示迁移结果，不运行建表或迁移；初始化和迁移仅由显式命令在授权流程下进行。
- 验收：旧库运行 doctor 前后比较完整表清单、schema 与版本；覆盖无版本、旧版本、新库和异常场景，测试必须使用临时或内存库。

### C14-03 · P2 · 核心推荐正向判定未接入实际业务

- 位置：`app/services/raffle/core_recommend.py:35`，`app/services/discovery/service.py:457-512`，`app/services/raffle/provenance.py`，`app/web/routes/pages.py:184-202`。
- 证据：仓库业务代码中未发现 `evaluate_core_recommend` 调用；候选生成将 `core_recommend` 设置为 false，页面读取 tags。新函数的单元测试不能证明核验后的实际业务流程会更新并展示推荐。
- 建议：建立并测试官方证据、核验状态、推荐判定、持久化和页面展示的完整闭环；候选或证据不足继续保持未知/非推荐，明确证据过期与撤销后的降级。
- 验收：使用隔离数据库通过真实服务入口验证正例、候选、证据不足、排除条款及证据撤销；检查 API 和页面，不能仅直接调用判定函数。

### C14-04 · P1/P2 · 正向规则不能证明跨境或官方身份

- 位置：`app/services/raffle/core_recommend.py:28-85`。
- 证据：直接调用判定函数，以“中国出发 上海至北京免费机票抽奖”、`prize_is_flight=True`、非空链接和 `verify_status=verified` 输入，返回 `confirmed_mainland_outbound`。该示例是国内航线；函数接收的 `source_kind` 也没有用于校验。
- 当前影响：该函数尚未接入实际业务，以上误判是潜在风险，并非已证明页面上出现了错误推荐。
- 建议：以可核查的官方来源证据及明确国际/跨境航线为正向条件，不能仅依赖“中国出发”或非空 URL；无法确定目的地、规则或官方身份时保持未知。不要凭空自动核实资格。
- 验收：增加内地国内航线、境外目的地明确/不明确、社区链接冒充官网、排除内地、活动范围不清、旧证据过期等样本，并在 C14-03 的端到端流程中验证。

### C14-05 · P2 · 部分 CLI 命令忽略迁移报告

- 位置：`app/db/session.py:153-163`；如 `app/cli.py:103,143,306` 等调用。
- 证据：多个命令接收 `prepare_engine` 返回的 `_mig`，但不展示或处理。对旧库或版本未知的情况，用户不一定能得到可操作提示。
- 建议：统一输出迁移状态；按命令风险明确允许只读、拒绝写入或提示人工备份迁移的行为。不要自动操作正式库。
- 验收：隔离测试无版本、版本落后、版本不可读和正常状态；确认提示可见，写操作边界符合设计。

### C14-06 · P2 · 需求矩阵和样本覆盖需修正

- 位置：`docs/REQUIREMENTS_MATRIX.md`、`docs/SPRINT_CLOSEOUT_PLAN.md`、`scripts/label_samples.py`。
- 证据：计划的 I1 目标为至少 30 条标注样本，目前脚本为 20 条；需求矩阵将浏览器拦截、核心推荐三态及旧库不改表列为 done，但上述证据显示至少需要 partial。
- 建议：逐项更新完成状态及证据，扩充带来源和预期结果的标注集，覆盖真实允许使用的样本和合成负例；不得以单元测试数代替 104 项验收。
